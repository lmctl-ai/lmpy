# S1: arrays and dense linear algebra

Ops: `array_import`, `array_inspect`, `la_lstsq`, `la_lstsq_to`, `la_props`, `la_decomp`
(plus the S0 `la_solve`/`la_solve_to`, whose array loader now accepts the wider dtype set).
Contracts, statuses, limits and decomposition conventions are in the README. Tests were
written first (commit 5e62cc0 was red against the S0 binary: `s1_arrays` 28 failures + 45
errors, `s1_la` 32 failures + 1 error across subtests; then green).

## Independent oracles (never the worker checking itself)

| Op | Oracle in tests |
|---|---|
| `array_import` | hand-written strict safetensors reader (offset contiguity, 8-byte alignment, exact coverage); `np.save` inputs; bit-exact comparison of 1000 random binary64 incl. denormals and -0; CSV cases written by hand |
| `array_inspect` | numpy min/max/nanmin semantics, `math.hypot` (correctly rounded to <1 ulp) for the norm, overflow/underflow vectors (1e200, 5e-324) |
| `la_lstsq` | exact rational least squares (`fractions`, normal equations over Q) on random integer problems and on the doubles of a 12x5 Hilbert system; NIST StRD **Longley** (certified 15 digits) and **Wampler 1**; closed forms (exact quadratic, rank-1 minimum-norm `[1,1]`); `scipy.linalg.lstsq` called directly per driver |
| `la_props` | exact rational det/rank/inverse (Gauss-Jordan over Q), Hilbert(3) closed forms (det 1/2160, integer inverse, cond 524.0567775860644), norms by definition, `scipy.linalg.svdvals`, `numpy.linalg.cond` |
| `la_decomp` | `scipy.linalg.svd/qr/eigh/eig/cholesky/lu` called directly (same LAPACK driver, so signs agree on this image), identities (orthogonality, A = QR, A = PLU), closed forms (2x2 symmetric, rotation eigenvalues +-i, companion roots 1,2,3, Cholesky [[2,0],[1,2]], LU of [[1,2],[3,4]]) |

NIST log relative error, measured on aarch64 through the CLI (test thresholds in parentheses):

| Problem | gelsd | gelsy | gelss |
|---|---|---|---|
| Longley coefficients, min..max LRE (>= 9) | 10.8..12.9 | 11.1..13.0 | 10.8..12.8 |
| Longley residual sum of squares (>= 8) | 11.9 | 12.9 | 12.6 |
| Wampler 1 coefficients, min..max (>= 7) | 8.8..14.5 | 9.6..14.7 | 8.8..14.5 |
| Hilbert 12x5 vs exact rational (>= 10) | 12.1 | 12.0 | 12.1 |

NIST Filip (10th-degree, 82 points, cond ~1e15) was not added: it needs the 82 certified
data pairs and 20+ digit arithmetic that I could not verify offline, and double precision
normal-equation or QR solvers are known to fail it. The exact-rational Hilbert system covers
the same "ill-conditioned but verifiable" ground with data that can be checked in the repo.

## Safety work

* The safetensors reader gained `list_tensors` (header-only validation, no payload read), the
  dtypes I32/U8/BOOL, and rank/size caps for the selected tensor taken from the header before
  `resize` (the S0 check also lived there but conflated dtype with size).
* `.npy` headers are parsed by a closed hand-written grammar. The S0 `std::regex` is gone: a
  64 KiB header could drive libstdc++'s recursive matcher deep; regression test with a 65 KB
  padded header.
* `tests/safetensors_fuzz.cpp`: 20000 deterministic header/length/truncation mutations of three
  seed files through `list_tensors`, `read_bundle` and `read_tensor` under ASan+UBSan
  (leak detection on), plus a lying 800 GB header. `pycli_asan` is the whole CLI built with
  the sanitizers; `s1_arrays` runs again against it (`s1_arrays_asan`), including a Python-side
  mutation fuzz of 270 files x 3 refs. Leak detection is off for that run because LeakSanitizer
  costs 4.4 s per process in this container.
* The ASan harness has a second, structure-aware phase (10000 always-valid-JSON headers whose
  dims, offsets, dtypes and keys are mutated, including 0, 2^63-1, 2^32 x 2^32, swapped/gapped/
  overlapping offsets and duplicate keys); it fails the run unless >= 10 % of them get through
  header parsing and payload reading (measured ~53 %; the random-byte phase reaches the payload
  checks only ~4 times in 8000). `RLIMIT_AS` (64/256 MiB) is **not** applied to the ASan harness
  (sanitizers reserve terabytes of address space). It is applied by the Python CLI tests in
  `tests/s1_arrays.py` (sparse 160 MB file with a lying header; ~270 mutated files x 3 refs)
  against the normal, non-sanitized binary.
* Sizes are checked before spawning: inline 1000, referenced 200000, outputs 2,000,000 numbers
  (a full QR/SVD of a tall matrix is m*m numbers and is refused with OUTPUT_TOO_LARGE), CSV 32 MiB.
* Worker output files are verified (count, dtype, shape, byte size, key grammar) before the
  C++ side writes the artifact; temp output files are on the signal-cleanup list.

## Deviations and open problems

* `la_lstsq_to` is an extra op (the `la_solve_to` pattern) rather than an optional `out`: access
  must be static per op, and a write op may not silently skip writing.
* `la_props` withholds the inverse (SINGULAR) when numpy's default rank test says rank < n.
  That is stricter than `la_solve`, which still solves `diag(1,1e-20)` and warns. Chosen
  because an inverse of a numerically singular matrix is not a result worth returning;
  documented in the README.
* The `what` default of `la_props` is applied in C++, not in the schema: lmscript's schema
  loader rejects an array default combined with an item enum.
* Safetensors artifacts are always F64 (qr pivots I64): `array_import` converts F32/I32/etc.
  exactly instead of preserving the dtype.
* Eigen/singular vector signs and eig phases are LAPACK's and are not portable; amd64 has not
  been run (host cannot execute it), so the comparisons against scipy are same-image checks.
* NO_CONVERGENCE cannot be provoked with finite small input; it is tested by forcing the
  scipy call to raise `LinAlgError` and asserting the status mapping and absence of output.
* Disk and time: `s1_la` takes ~80 s (about 140 CLI calls, each starting a Python worker with a
  ~0.3 s NumPy/SciPy import). `ctest` total is ~160 s.

## Review fixes (Opus + Fable S1 reviews)

| Finding | Disposition |
|---|---|
| Inline cap (Opus 1) | Fixed. `la_lstsq` counts x + residues + singular values (<= 1000) before spawning; `la_lstsq_to` moves residues and singular values into the artifact (tensors `residues`, `singular_values`, inline `residues_count/sum/max`) even when small; a generic guard rejects any result with > 1000 inline array numbers ("CAP exceeded") |
| eig false NUMERICAL_FAILURE (Fable 1) | Fixed. Residual is scaled by `||A||_F ||V||_F` (eigh too); nilpotent/defective fixtures incl. `[[1,-1],[1,-1]]`; `vr_cond` reported and a `NumericalWarning` when `vr_cond > 1/sqrt(eps)` (Opus 4) |
| Unsupported dtype fails whole file (Opus 2) | Fixed. Full spec dtype table for validation/listing; F16/BF16/etc. fail only when selected (`UNSUPPORTED_DTYPE`). Unknown dtype *names* still reject the file: their size is not defined |
| Fuzz coverage / RLIMIT claim (Opus 3) | Fixed (structure-aware phase, doc corrected above) |
| NOT_FOUND (Fable 3) | Fixed. A missing input file or tensor key is `NOT_FOUND` (4), as torchcli does for `TENSOR_NOT_FOUND`; malformed refs and everything else stay validation errors (2). Syntax is checked before existence. rcli uses 2 for missing files; pycli follows torchcli/protocol 6.1 |
| Failure envelope diagnostics, schema statuses (Fable 2, 6) | Fixed (`kind`, `driver`, `message`, `reconstruction_error`, `rank`, `residual_norm` forwarded; schema lists NUMERICAL_FAILURE) |
| trace on rectangular (Fable 4) | Fixed: requires a square matrix. The default `what` for rectangular input is rank, cond, norm |
| Silent reshaping (Fable 5) | Fixed: `{shape,data}` takes flat data (row-major) or nested data with exactly the declared shape |
| cond of singular input (Fable 6) | Fixed in code: `Inf` when rank-deficient under numpy's default tolerance (matches README) |
| Sign-exact scipy comparisons (Fable 7) | Fixed: svd/qr/eigh vectors compared after per-column sign alignment, plus invariants; LU/Cholesky stay exact (pivoting/positive diagonal are convention-defined) |
| No safetensors-ref decomposition test (Fable 7) | Added (F32 and I64 refs through svd, lu, lstsq, props) |

S7 API migration: all successful file writes use `outputs_in_artifact:true` and
