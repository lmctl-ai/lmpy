# S8b-2: graph operations and the stats_dist long tail

S8b-2 finishes the S8b scope (docs/s8b.md): `graph_paths(_to)`, `graph_flow(_to)` and 31 `stats_dist` families (the S8a ten plus 21) with ten functions. The review round against 52f0267 is recorded in docs/s8b2-review-notes.md. Everything follows the S7/S8a/S8b-1 conventions: caps before spawn and again in the worker, the cooperative
`time_limit`, domain statuses instead of silent wrong numbers, `_to` twins with the one `artifacts[name]` seven-field descriptor (nothing is written for a non-OK status), one table format (`.npz`) for edge lists and results.

## Dependency
networkx 3.7 (BSD-3-Clause, `py3-none-any` wheel, one hash in both lock files). It is pure Python, imported only inside the graph operations (the worker warms it in the trusted phase, before the import guard, because networkx imports
helper modules lazily). `licenses/networkx/LICENSE.txt` is hash-checked by `scripts/notices.py`, the notice inventory regenerates byte-for-byte (`tests/notices_inventory.py`), and `scripts/prune.py` drops networkx's test directories. No graph file format
is accepted: edges come from a stored table (`frame`, columns named explicitly, int64 or string ids; categories are strings) or inline `records`; GraphML, GEXF, pickle and friends do not exist as inputs. Cost: see docs/timings.md.

## graph_paths / graph_paths_to
* `method` dijkstra (non-negative weights, `BAD_PARAM` otherwise), bellman_ford (negative weights allowed; `NEGATIVE_CYCLE` with a `cycle` witness when a negative cycle is reachable from the source, or anywhere for all pairs: the all-pairs witness comes from networkx's Bellman-Ford run from a super source joined to every node), bfs (hop counts; no weight column).
* Unreachable rule: an unreachable node never has a distance. With a `target` that cannot be reached the status is `UNREACHABLE` (no `path`, no `length`); the node listing and the node table report `n_unreachable` and leave distance/hops/predecessor missing.
* Parallel edges keep the lightest, undirected edges are mirrored, weights are at most 1e15 in magnitude (`BAD_DATA` before spawn; a sum of 1e5 such weights stays finite). Self loops: a non-negative self loop is ignored by every method and never trips the negative-weight rule or `DUPLICATE_EDGE`; a negative self loop is a negative cycle of one node, so bellman_ford reports `NEGATIVE_CYCLE` with `cycle: [u]` when it is reachable (all pairs: anywhere) and dijkstra / k_shortest reject it as the negative weight it is (`BAD_PARAM`). Zero-weight edges are edges (checked against Floyd-Warshall). Predecessors and hop counts come from a tight-edge BFS of the final distances (tight within 1e-12 relative, so float weights summed in another order still count), so zero-weight cycles never produce a predecessor loop (the path with the fewest legs among shortest ones).
* `k_shortest` <= 10 (Yen, networkx `shortest_simple_paths`) needs a target and non-negative weights; the `paths` list has `nodes`, `length`, `hops` ascending by length.
* All pairs (`_to` only): integer ids, an n x n F64 `distance` matrix (NaN = unreachable) and the int64 `nodes` (ascending) in a `.safetensors` file. scipy.sparse.csgraph computes it (Dijkstra, Johnson for bellman_ford, unweighted Dijkstra for bfs). The bound is n <= 5000 AND n*n <= 1,900,000
  matrix numbers (about 1377 nodes: the artifact budget), rejected before the worker starts, so a 5000-node request answers `OUTPUT_TOO_LARGE` immediately instead of building 25 million numbers.
* Inline results hold at most about 900 numbers (a path of at most 900 nodes, at most 450 listed nodes). Larger answers need `graph_paths_to`: `OUTPUT_TOO_LARGE` (always `COMMAND_FAILED`, exit 1) says so, before the worker starts when the size is known up front (node listings, the all-pairs matrix) and from the worker otherwise (path length, k_shortest, flow edges); the message names what to change (the write form has no `target`/`k_shortest`, so a long k_shortest answer asks for fewer paths); no artifact is created.
* Caps: 100000 edges, 100000 nodes. String ids round-trip exactly (including numeric-looking strings, which never become integers); int64 ids stay int64. Node ids are checked before spawn in both the frame and the records form: integers must fit int64 (an unsigned 2^63 is `BAD_DTYPE`, not a wrapped negative), strings and category levels hold no NUL (`BAD_DATA`) and are at most 256 bytes (`INPUT_TOO_LARGE`): the node tables store ids fixed-width at the longest id, so 100000 nodes cost at most 25.6 MB, never the gigabytes a single long id could demand.

## graph_flow / graph_flow_to
* `kind` max_flow (Dinitz), min_cut (value, cut edges, source side; verified equal to the flow value), min_cost_flow (network simplex; integer costs, negative allowed; `source`/`sink`/`flow_value` or `supplies` pairs).
* Capacities: int64 or float64 in [0, 1e15] and min_cost_flow costs in [-1e12, 1e12], both rejected before spawn (`BAD_DATA`); **integer capacities are recommended** and give exact results (`integral: true`, tolerance 0). With float capacities every edge carrying flow is listed (only rounding residue below 1e-12 of the value is dropped) and the returned flow is re-verified against the edge list (conservation, capacity) within
  `tolerance = 1e-9 * the flow value`; a violation is `NUMERICAL_FAILURE`, never a wrong answer. The tolerance follows the value and not the largest capacity, so a 1e9 sentinel link never hides the 0.6-unit branches behind it. Summed parallel capacities and the flow value are reported as plain numbers; a min_cost_flow `cost` outside int64 is a double plus the exact decimal string `cost_exact` and a warning.
* Domain statuses: `INFEASIBLE` (supplies cannot be routed), `UNBALANCED` (supplies do not sum to zero), `UNBOUNDED` (a negative-cost cycle of unbounded capacity, or an unbounded augmenting path), `NUMERICAL_FAILURE`, `TIME_LIMIT`.
* Parallel edges: summed capacity for max_flow/min_cut; `DUPLICATE_EDGE` (validation) for min_cost_flow because costs cannot be merged honestly. Self loops carry no useful flow and are dropped (repeated self loops are not `DUPLICATE_EDGE`), with one exception: min_cost_flow saturates a negative-cost self loop because that lowers the cost (the loop appears as a flow edge `(u, u, capacity)` and contributes `capacity * cost`). Node ids must be int64 or strings (same rules as for paths) and the source/sink must occur in the edges (`UNKNOWN_NODE`); supply amounts and `flow_value` fit int64.
* Inline <= 300 flow edges or cut edges (`OUTPUT_TOO_LARGE` otherwise); `graph_flow_to` writes `(from, to, flow)` or `(from, to, capacity)` as a table (a zero-flow answer is a valid zero-row table). Caps: 20000 edges and nodes.

## stats_dist long tail
Parameters are validated in C++ from one per-family table (`dist_table` in `src/s8.hpp`) mirrored by `dist_frozen` in `py/s8.py`; unknown parameters, missing required ones, out-of-domain values and magnitudes above 1e12 are `BAD_PARAM` before any spawn.
Functions: pdf, logpdf, cdf, logcdf, sf, logsf, ppf, isf, moments, rvs (rvs keeps the S8a seed rules and echo: required explicit seed, PCG64, a shorter n is a prefix of a longer one for every family). Discrete families are integer-valued F64 and `pdf`/`logpdf` mean the mass function; their `ppf(0)` and `isf(1)` are the first support point (scipy's "lower bound minus one" never leaks).
Inline: x <= 1000 points, a one-dimensional vector (`BAD_PARAM` otherwise; rvs n <= 1000, moments are four numbers); `stats_dist_to` evaluates at up to 200,000 points (the referenced-array cap) or samples up to 1,000,000 values into an F64 vector artifact, NA inputs becoming NaN there (`n_missing` counts NA inputs, `n_nan` the NaN ones).
The prefix property for the compound samplers (nct, skewnorm, betabinom, levy_stable) comes from two PCG64 streams, `PCG64(seed)` and `PCG64(seed).jumped()`: scipy draws the two full-length arrays of these families one after the other from one stream, so its first value would depend on n. `streams: 2` is echoed for them; the other families use scipy's or numpy's one-stream sampler unchanged.

| Family | Parameters (all `loc` default 0, `scale` default 1 where listed) |
|---|---|
| norm, t, genextreme, genpareto, skewnorm, johnsonsu, nct, ncf, vonmises, truncnorm, weibull_min, cauchy, laplace, logistic, gumbel_r, pareto, rayleigh, f | scipy's names plus `loc`, `scale` (see the README table for the shape parameters) |
| uniform, expon, gamma, beta, lognorm, chi2, poisson, binom | the S8a names (`low`/`high`, `scale`, `shape`/`scale`, `a`/`b`, `mu`/`sigma`, `df`, `lam`, `n`/`p`) |
| zipf, betabinom, nbinom, geom | integer-valued; `loc` must be an integer |
| levy_stable | alpha in (0, 2], beta in [-1, 1], `loc`, `scale`: scipy's default S1 parameterisation, in which alpha = 2 is the normal with standard deviation sqrt(2) * scale (pdf(0) = 1 / (2 sqrt(pi)), not 0.3989) and alpha = 1, beta = 0 is Cauchy; a warning on every pdf/cdf call says the integration is slow and only about 1e-6 accurate; at most 200 points |

**Where scipy's parameterisation differs from R's (and from textbooks):** gamma scipy `scale` = 1 / R `rate`; norm `loc`/`scale` = R `mean`/`sd`; t, chi2, beta, binom and poisson agree up to names; genextreme scipy `c` = -xi (the GEV shape xi of R `evd` and most texts has the
opposite sign); genpareto `c` = xi; truncnorm `a`, `b` are standardised bounds, the support is `loc + scale * [a, b]`; nbinom counts failures before the n-th success with support 0, 1, ...; geom has support 1, 2, ... (R `dgeom` starts at 0); lognorm here takes the
`mu`, `sigma` of the underlying normal (scipy takes `s` and `scale = exp(mu)`); vonmises variates are wrapped into [-pi, pi] after adding `loc`, so `loc` rotates the circle and the linear mean is not `loc`; levy_stable depends on the stable parameterisation (S1 here).

**Work caps found by measuring** (docs/oracle-findings.md items 3 to 6): betabinom n <= 5000 (scipy sums the mass function); zipf cdf/sf need x - loc <= 1e5 (the sum starts at loc + 1) and a quantile beyond loc + 1e5 is reported as `NA` for that point with the status `OUT_OF_RANGE` and `n_out_of_range` (the other points keep their values; the write twin writes nothing); scipy's own failures (e.g. zipf.ppf for a < 2) are `NUMERICAL_FAILURE`;
vonmises (kappa <= 1e5) and levy_stable evaluate at most 200 points; nct |nc| <= 1000 and df >= 1e-8 (Boost's noncentral t aborts the process for smaller df); lognorm |mu| <= 700 (exp(mu) must stay finite); nbinom and geom p >= 1e-15 (1 - p must differ from 1: scipy's C quantile search never returns at p = 1e-300 and numpy's integer samplers saturate at 2^63 - 1); every other magnitude is capped at 1e12 except Student-t `df`, which is unbounded because df = 1e300 is the normal limit. Moments that are infinite or undefined come back as `NA` and are listed in `moments_undefined`.

**Numerical repairs on top of scipy** (each one tested against an independent reference): nct pdf/logpdf fall back to adaptive quadrature of the defining integral where scipy's closed form underflows to 0 inside the body of the distribution (large nc; about 1e-8 relative); vonmises cdf/logcdf/sf/logsf wrap x onto the circle loc + scale * [-pi, pi] first (so no probability outside [0, 1]) and ppf(0) / ppf(1) are the circle ends; weibull_min moments use the mean from Gamma(1 + 1/c) and central moments by quadrature, so sharp shapes keep their digits (c = 1e6 gives the Gumbel-min limits, not noise); geom and nbinom draws that numpy refuses or saturates at 2^63 - 1 (a mean beyond the integer range, e.g. n = 1e12 with p = 1e-15) report `NUMERICAL_FAILURE`; a one-point levy_stable evaluation at alpha = 1 is lifted from scipy's 0-d result.

**Warm-up and budget:** the worker warms scipy's lazy imports with canonical cheap parameters for the requested function only; the caller's parameters are evaluated under the cooperative `time_limit` (every stats_dist call now carries the process budget like the other S8 operations), so an unbounded quantile search (nbinom ppf at p = 1e-300) is `TIME_LIMIT`, not a 50 s kill, and zipf with a close to 1 answers at once.

## Oracles and tests
* `tests/s8b2_graph.py` + `tests/oracle/s8b2.py`: pure-Python Dijkstra / Bellman-Ford / BFS / Floyd-Warshall, brute-force k shortest simple paths, Edmonds-Karp with the residual min cut, successive shortest paths for min-cost flow; textbook graphs (CLRS paths, CLRS flow = 23), seeded fuzz,
  min-cut = max-flow duality, string and int id round trips, the 1377/1378-node all-pairs boundary, the negative-cycle witness, pre-spawn caps with a missing interpreter, the cooperative budget (`TIME_LIMIT` in well under 20 s with a 50 ms budget).
* `tests/s8b2_dist.py`: hand formulas and mpmath (40 digits) for every new family, cdf(ppf) / log / isf identities, moment closed forms, seeded KS and moment checks for rvs, the validation table, the work caps and the evaluation twin.
* `tests/s8b2_review.py`: the review regressions (docs/s8b2-review-notes.md): fixed-seed fuzz of random graphs against the pure-Python algorithms, random networks against the `opt_linprog` LP oracle (max flow, min cut, min cost), every family against mpmath, the warm-up/budget contract, far-tail log functions, golden PCG64 streams and exact hop counts (Kimi's five mutations; `scripts/check-s8b2-review-mutations.py` runs them in scratch copies).
* Recipes (all pass in real, `--check` and `--dry-run` modes): `graph-route-plan.lms` (hand values on the CLRS graphs), `oracle-dist.lms` (R through rcli, 217 values, 1e-12 relative; continuous ppf 1e-10), `distributions-tour.lms` (closed forms; no other tool).

## Measured worst cases
`scripts/measure-s8b2-caps.py` runs the caps and adversarial shapes inside the hardened container (2 CPUs, 4 GiB, read-only root, no network); the result is in docs/measurement-s8b2-caps.txt and summarised in docs/timings.md.
The first run found the three problems that the caps above fix (betabinom n = 1e9 crashed the worker, zipf with x to 1e9 reached the 50 s hard kill, `min_cost_flow` on a 20000-edge chain is a `TIME_LIMIT` rather than an answer); after the fixes the slowest call
is a cooperative `TIME_LIMIT` that returns in under 15 s with the default 10 s budget, nothing reaches the 50 s kill, and the cgroup peak is 0.71 GB.
