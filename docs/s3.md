# S3: safe expressions, optimisation, quadrature, roots

Ops: `opt_minimize`, `opt_least_squares`, `num_quad`, `num_root` (all read; no files written, no seeds: every
algorithm used is deterministic). Contracts, statuses and limits are in the README section "S3". Tests were written
first (commit 1340579 ran red against the S2 binary).

## Expression subsystem

* **One grammar, two languages.** `expr-spec.json` and `tests/expr-corpus.json` (13 accepted / 57 rejected) are
  byte-identical to rcli's; their SHA-256 are pinned in `tests/s3_expr.py` and `scripts/expr-parity.py` (run on the host,
  where the rcli checkout exists) additionally proves that the only differences between the two C++ parsers are
  the namespace/macro names and the vector-index extension. The C++ binary reports the spec hash with
  `--expr-spec-hash`, the Python side computes the hash of the file the C++ side wrote for it, and the tests compare both
  with the pinned value.
* **Extension (not in the shared spec):** vector unknowns. `Parser(..., dims)`: a name in `dims` must be followed by
  `[<unsigned integer literal>]` (<=6 digits, no leading zero, below the length); a scalar followed by `[` stays a
  syntax error exactly as in rcli. The shared corpus runs with empty `dims` (so it still pins rcli behaviour);
  `tests/expr-corpus-pycli.json` pins the extension (7 accepted, 26 rejected). Spec v2 was not needed because indexing is a
  parser feature, not a function.
* **Python side:** `py/numerics.py` (embedded before `worker.py`, assembled by CMake and mirrored by `tests/oracle/s3.py`).
  `compile_expression` walks the AST **iteratively** (explicit stack; a 200000-deep hostile AST is rejected at the 513th node
  without touching the interpreter stack) and emits a flat postfix program of function objects from `function_table()`
  and `operator_table()`. It re-validates node kinds, arities, constants, declared names, vector indices and the node cap;
  any disagreement is `ExprMismatch` -> `INTERNAL_ERROR/EXPR_SPEC_MISMATCH`. `call` nodes cannot name `ifelse`, `ifelse` has
  its own node kind. A spec function without a binding fails `check_bindings`. There is no `eval`, `exec`, `compile`,
  `getattr`, `ast`, `importlib`, `pandas.eval`, `numexpr`, `sympy` anywhere (`tests/s3_expr.py` greps the assembled source).
* **Guards:** a shared `Guard` counts every objective, gradient, constraint and residual call (`max_evals`, default 500000,
  cap 2M -> `EVAL_LIMIT`) and checks a monotonic wall-clock deadline (call timeout minus 10 s -> `TIME_LIMIT`) on every
  call; the C++ child timeout stays the last layer. Numpy runs under `errstate(all='ignore')`; non-finite values are
  detected and counted explicitly, so a long run cannot accumulate millions of Python warning records.

## Solver conventions

* `opt_minimize`: SciPy's `minimize` with the six methods of the brief; bounds as `Bounds`, constraints as dict constraints,
  finite-difference gradients unless one expression per scalar unknown is given (arity checked in C++, compared with a
  finite-difference gradient at `x0`, mismatch -> warning). Results re-evaluate constraints independently; a violation above
  1e-6 downgrades `OK` to `NO_CONVERGENCE`.
* `opt_least_squares`: `least_squares` with `x_scale="jac"`; `std_err` from a **central-difference Jacobian at the solution**
  (scipy's 2-point Jacobian uses an absolute step 1.5e-8 and was off by 2.6e-5 relative for Misra1a's b2 ~ 5e-4; the
  analytic-Jacobian standard errors match NIST to 9 digits; the central-difference ones to 7-9 digits). Column-equilibrated SVD
  rank test at 1e-8 (above finite-difference noise, so exactly collinear models are detected) and the `curve_fit`
  scaling `2*cost/(m-n)`.
* `num_quad`: `quad(full_output=1)`; QUADPACK's message is returned and the status is `NO_CONVERGENCE`, never a warning on
  stderr. `num_root`: bracket endpoints are evaluated first (non-finite -> `NONFINITE_BRACKET`, same sign -> `BAD_INTERVAL`).
* Unknowns are ordered **by name** (lmcpp's `Json` is an ordered map in insertion order, and JSON objects are unordered, so
  caller key order must not matter; regression test with swapped key order).

## Safety tests

* All 70 shared corpus cases and 33 vector-index cases run through the C++ parser (CTest `shared_expr_corpus`,
  `vector_index_expr_corpus`); the 57 shared negatives additionally run through `opt_minimize` with a nonexistent
  interpreter (exit 2, never 8: nothing spawns).
* `expr_parser_asan_fuzz`: 15000 mutated corpus expressions with random vector declarations under ASan+UBSan; every accepted
  AST is checked against the caps and the declared names/dims (the invariants the Python builder re-checks).
* Hostile list (`__import__`, dunder attributes, lambda, comprehension, string/format-string literals, `**`, `exec`, `open`, hex/
  binary/underscore/complex literals, homoglyphs and combining characters, fullwidth digits, NUL, RLO, empty input, 33-deep
  parentheses, 17-deep calls, 600-term chains, 2049 bytes, `x[huge]`, `x[-1]`, `x[1.5]`): rejected in C++ for `num_quad` and
  `opt_minimize` without spawning. `2^2^2^2^2^2^2^2` (2^65536) is legal and ends as `NON_FINITE` / `NONFINITE_OBJECTIVE`.
* Builder tests: ~40 hostile ASTs (unknown/aliased functions such as `__import__`, `eval`, `getattr`, `system`; `**`, `%`; wrong
  arity; non-string names; booleans/NaN/Inf/strings as numbers; indices out of range, negative, boolean, float; unknown node
  kinds; non-dict nodes) are all `ExprMismatch`.

## Deviations and open problems

* Table (`.npz`) refs are not accepted as `data`; arrays come from inline JSON, `.npy` or `.safetensors#key`. Use `array_import`
  on an exported CSV column. (The brief allows "table/array refs"; reading NPZ columns in the worker needs the frame
  reader's metadata plumbing and was cut.)
* The method enum is the six methods of the brief; TNC and COBYLA (design-opus) are not offered. `num_root` is bracketed only.
  `opt_root` (systems) and ODEs are later slices.
* The vector-index extension means a vector expression cannot be given to rcli. Scalar expressions are interchangeable **for the shared
  function table as pinned by `tests/expr-semantics-golden.json`** (R's own answers over an edge-value grid), including NaN conditions,
  `choose`/`lchoose`/`beta` domains and `gamma`/`digamma` poles; the only documented numerical difference is `choose`/`lchoose` with
  `|k| >= 1e9`, where R and SciPy use different log-gamma code paths and only the finite/non-finite class is compared.
* `TIME_LIMIT` is cooperative: a single expression evaluation over 200000 rows x 512 nodes (~0.3-0.6 s) cannot be
  interrupted; the 10 s margin to the hard kill covers it.
* Robust-loss `std_err` is approximate (scipy's loss-modified Jacobian); after a non-converged fit it is flagged.
* No amd64 run (host cannot execute it): tolerances for Himmelblau/Rosenbrock minima are 1e-4..1e-5, NIST LRE >= 6.
* `dryrun` does not simulate read operations in lmcpp; S3 ops are pure reads.

## S3 review fixes (Opus, Fable, Astra)

| Finding | Disposition |
|---|---|
| Opus 1/4: gradient check outside the guard; `EVAL_LIMIT` escaping as `PY_ERROR` | Fixed. Start point, gradient check (analytic + n forward differences), solver, final residual and the standard-error Jacobian all go through `Guard.tick()`, which checks the cap and the deadline *before* admitting an evaluation (`evals <= max_evals` always). Any `SolverStop` in any stage becomes `EVAL_LIMIT`/`TIME_LIMIT`; a stop during the post-solver steps keeps the solver's status and reports `cov_status: UNAVAILABLE_BUDGET`. 64 unknowns x 200000 rows + gradient + 15 s call timeout now ends in `EVAL_LIMIT`/`TIME_LIMIT`, not exit 7 |
| Opus 2: residual-mode OOM | Fixed. C++ bounds residual count (vector expressions count `rows`, scalars 1) x unknowns <= 20e6 before spawn (`INPUT_TOO_LARGE`); the worker re-checks the real count after the first evaluation |
| Opus 3 / Astra 1-2: R semantics | Fixed and pinned (see the semantics section of the README and the golden grid). `lchoose` uses `-log(n+1) - lbeta(n-k+1, k+1)` like R, so `lchoose(2000,1000)` = 1382.268; `choose`/`lchoose` round k and handle negative n; `beta`/`lbeta` domain as R; `ifelse` and `& \|` three-valued |
| Fable 1: standard errors for ~0 parameters | Fixed (adaptive step ladder using the solver's Jacobian column norms and the residual scale; condition number reported; ill-conditioned flagged) |
| Fable 2/3 | Fixed (exact-root end returns `iterations: 0`; sign comparison via `copysign`; non-finite analytic gradient -> `NONFINITE_GRADIENT`) |
| Fable 4 | Fixed in the message (`points` hint); documented in the README |
| Fable 5 | Per-component vector bounds implemented; 1e-8 singularity threshold and best-point-may-be-infeasible documented; `xtol` described as bracket width |

Known R quirks reproduced on purpose (they are what rcli returns): `choose(Inf, k)` is NaN for k >= 30, `lchoose(Inf, k)` NaN for k >= 2,
`choose(n, Inf)` is 0 only for finite n >= 0 and NaN otherwise.
